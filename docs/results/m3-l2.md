**24 h criterion not met yet.** The second run lost the websocket twice within two minutes
(`ConnectionClosedError` while the M4/M5 jobs saturated the CPU), and each loss is a sequence gap; the
book resynced at the next snapshot and every snapshot check still matched. The recorder now keeps
two redundant connections and deduplicates by update id (ADR 0011). That removes the gap when one
connection drops while the other is in step; it does not yet fill a hole if one connection runs
more than one diff ahead of the other (audit finding M9-4; fix: a small reorder buffer keyed by U). The cloud container itself was restarted about every 1 to 2 hours today, killing every long
run, so the 24 h run needs a host that stays up (the user's machine, or a cloud session left
idle).

Pass criterion for the open item: `python -m tickforge.l2 check <dir> --require-hours 24` exits 0
(0 gaps, 0 mismatches, >= 24 h).

## Reproduce
```bash
pip install websockets
PYTHONPATH=python python -m tickforge.recorder --symbol BTCUSDT --out data/raw/rec/btcusdt --hours 24
PYTHONPATH=python python -m tickforge.l2 check data/raw/rec/btcusdt --events /tmp/btc.l2 --require-hours 24
./build/engine/tf_l2replay /tmp/btc.l2
python data/fetch.py binance-trades --symbol BTCUSDT --date 2026-11-10
PYTHONPATH=python python -m tickforge.binance_dump data/raw/binance/BTCUSDT-trades-2026-11-10.zip
pytest -q tests/test_l2.py tests/test_binance_dump.py
```
