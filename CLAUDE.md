# CLAUDE.md: conventions for Tickforge

This file is the contract for anyone (human or agent) touching this repository.

## Prime directives

1. **Every change ships with a Verify command.** A PR description names the exact command that proves
   it works (`ctest`, `pytest`, a benchmark, a cocotb test). If something cannot be verified yet, say so
   and name the milestone that will make it verifiable.
2. **The C++ engine is the golden model.** The Python reference book (`python/tickforge/refbook.py`) and,
   later, the RTL feed handler must match it **bit-exact** on committed fixtures (book digest + depth
   snapshots). Approximate equality is never acceptable for book state.
3. **Backtests do not lie.** No result is reported without costs, latency and an out-of-sample split.
   Every headline Sharpe is shown next to its deflated Sharpe. Signals that failed stay in the graveyard.
4. **Paper only.** No order-submission client for any real venue, no API keys with trade or withdraw
   permission, ever. Live connections are market-data only.
5. **Data is never committed.** Download scripts and checksums are. Fixtures in `fixtures/` are
   synthetic and generated by committed, seeded code; regenerating one is a reviewed change.

## Architecture Decision Records

- Hard-to-reverse decisions get an ADR in `docs/adr/`, numbered sequentially, from `0000-template.md`.
- ADRs are immutable once Accepted; supersede with a new ADR.
- Reference ADR numbers in code comments and PR descriptions.

## C++ standards

- C++20, builds warning-free with `-Wall -Wextra -Wpedantic` on GCC and Clang.
- Hot path (parse → book update) does no heap allocation in steady state and no virtual dispatch.
- Deterministic: no wall-clock reads, no unordered iteration that affects output, seeded RNG only.
- ASan + UBSan job must stay green.
- One responsibility per header; public headers in `engine/include/tickforge/`.

## Python standards

- Python 3.11+; pure-Python reference code favours clarity over speed.
- Tests in `tests/` run with `pytest -q` from the repo root.

## Branch / PR discipline

- Never commit directly to the default branch. One logical change per PR.
- PR description: what changed, **Verify command**, ADRs touched, roadmap milestone.
- Red CI never merges. Commit messages explain *why*.
